Module 3 · Design track

Working documents and notes

Two lectures on the highest-volume medium and the one nobody designs. A memo, a briefing note, a meeting record, a draft circulated for comment, a note to yourself. Written quickly, read once, and produced in a tool that has a design system built into it that almost nobody uses.

What this module is

This is the only module in the track that makes a substantial concession to reality. Everywhere else the recommendation is to choose good type and set it well. Here the recommendation is to use fonts that exist on a standard corporate Windows machine, because a document whose pagination breaks on the recipient's laptop has failed regardless of how it looked on yours. Butterick would object, he would be right in principle, and the concession stands. Lecture 17 makes the argument properly.

The second thing that separates this module is that the artefact you are designing is usually not the document. It is the template, or the style ladder, or the note format you will use two hundred more times. A single well-set memo is worth very little; a memo template that makes every memo readable is worth a great deal, and the effort is the same.

The two lectures split by that distinction. The first is about the mechanism: Word's style system, what it does, and how to configure it so the design survives editing by people who have never heard of a design system. The second is about format as a constraint, from the four-line memo header to Amazon's six-page limit, and about the parallel question of styling notes you write for yourself.

Prerequisites

All eleven foundations lectures, and ideally lecture 14, since a working document is a report with the ambition removed and most of the geometry reasoning transfers.

Where this module does not apply The font concession is specific to editable files circulated to other people. If you are producing a PDF, the fonts embed, nothing reflows, and the reports module applies instead. Do not import this module's compromises into a document that does not need them.

Module sequence

The mechanism, then the format

  • builtLecture 17: the Word document as a design system. The built-in style ladder and why it beats any custom one, inheritance from Normal, direct formatting as technical debt, Word's line-spacing quirk, and the corporate font problem including the 2024 move to Aptos.
  • builtLecture 18: memos, briefing notes and the page limit. The four-line header as a triage device, the decision note, what Amazon's six-page memo actually buys, prose against bullets, and designing notes for your future self.

Token specification

The building blocks are in 03_documents/DESIGN.md, which carries two profiles rather than one: Office, mapped onto Word's built-in style names with point sizes and spacing, and Notes, for Obsidian and Markdown, which is free to use the full house palette because it is read on one screen you control.
