Module 7 · Design track

Emails and newsletters

The last module, and the most constrained medium in the track. Email rendering is roughly twenty years behind the browser, one major client renders HTML through Microsoft Word, and the reader's software may rewrite your colours without asking. It is here because it is the clearest demonstration that a design system is mostly a set of decisions about what you cannot do.

What this module is

Every other module in this track has been about choosing well from a wide field. This one is about working inside a small one. No flexbox, no grid, no reliable max-width, no dependable web fonts, and a layout language that is HTML tables because nothing better survives. The design question stops being what would be best and becomes what will actually arrive.

That constraint turns out to be clarifying rather than merely limiting, which is the module's real lesson. When the palette of techniques is small, the remaining decisions are about content and structure, and the evidence suggests that is where the value was all along: the best-performing newsletters are the ones that look almost like plain text.

Two lectures. The first is the mechanism: what the clients do, what breaks, and the patterns that survive. The second is composition, the case for plain text, the legal obligations, and the closing argument of the whole course.

Prerequisites

All eleven foundations lectures. The blogs module is useful background, since email is the web with almost everything taken away, and the contrast is instructive.

This module dates fastest Client market shares, CSS support and the fate of the Word-based Outlook renderer are a snapshot of 2026 and will move. The reasoning is durable; the figures are not. Both lectures mark which is which, and the token file records the same caveat.

Where this ends

Lecture 28 is the last lecture in the track and closes the course rather than only the module. The argument it lands on is the one every module has approached from its own direction: restraint is not a style, it is what happens when you know what each element costs.
