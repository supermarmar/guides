Course companion

Claude engineering

Twenty-two lectures on working with a coding agent deliberately. The spine is Claude Code, the CLI harness, because that is where the practice is densest and most transferable. The course draws on two bodies of evidence: Anthropic's own engineering write-ups on context, harnesses, skills, and tools, and the working conventions built up on this machine, which appear throughout as worked examples rather than as invented illustrations. Assumes you have used an AI coding assistant and would now like to stop improvising.

How to use this

The lectures are sequenced from the constraint outwards. Part I establishes what an agent actually is and what limits it: the loop, the context window, the harness, and the model. Part II is the steering layer, the artefacts you write once so that you do not have to say the same thing in every session. Part III is verification, which is where the whole practice either holds together or collapses. Part IV widens from the terminal to the stack around it, MCP and the tools it reaches: Obsidian, Notion, the Microsoft 365 surface, and unattended runs. Part V is judgement: security, cost, and knowing when to close the laptop and write the code yourself. Status badges show what is built (built), planned, or a gap (source note is a stub).

One warning about shelf life. Claude Code changes month to month, so any lecture that lists flags and file paths will go stale faster than one that explains why the flag exists. The course concentrates the version-sensitive detail into Lectures 3, 9, 15, and 19, and keeps the other eighteen principle-led. When something here contradicts the current documentation, the documentation wins.

What is and is not covered

The course covers the engineering practice of directing a coding agent: how to constrain it, how to check it, and how to wire it into the tools you already use. It does not cover how large language models work. That belongs to the large language models module in the machine learning track, which handles pretraining, decoding, prompting theory, and responsible use, and which is worth reading first if the words "context window" and "sampling temperature" are not yet furniture. Nor does it cover building agents with the API or the Agent SDK beyond the point where those explain harness behaviour; that is a different course with a different audience. Building an agent rather than directing one belongs to the language engineering track, whose lecture on agents and ReAct covers the reasoning-acting loop, tool schemas, and the failure modes from the constructor's side rather than the user's.

It also does not cover the underlying engineering discipline. Version control, testing, code review, and continuous integration are assumed, and where they matter the lecture points at the software engineering track rather than restating it. The claim running through the whole course is that agentic practice is not a replacement for that discipline but a multiplier on it, in both directions: teams with strong verification get faster, and teams without it get worse code sooner.

Every lecture cites its sources by name. The external spine is Anthropic's engineering writing (context engineering, long-running harnesses, agent skills, tool design, code execution with MCP) and the Claude Code documentation, with Andrej Karpathy's Software 3.0 material supplying the framing for what changes when the program is a paragraph. The internal spine is the configuration on this machine, quoted as it stands.
