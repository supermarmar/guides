Forecasting evaluation and model-agnostic diagnostics

Time-series models need their own evaluation playbook because the IID assumption fails. Autocorrelation tests catch missed structure, walk-forward backtesting catches future leakage, and the KS and lift metrics close the model-agnostic toolkit.

Lecture 38 of 62 Reading time, 50 minutes Part V: tuning and assessment
Step 1

The 30-second version

Regression and classification metrics share a hidden premise: the rows of the test set are independent draws from the same distribution as training. Time-series models break that premise twice. Observations are dependent through time, so residuals carry information about other residuals. And the test set lives in the future, so any procedure that shuffles or randomly splits is a leak. Forecasting evaluation is the set of diagnostics that survive those failures. Residual autocorrelation tests (visual ACF, Durbin-Watson, Ljung-Box) catch the case where the model has fit the level of the series but missed a lag effect or a seasonality, leaving structure in the residuals that should not be there. Walk-forward backtesting evaluates the model the way it will actually be used: fit on $[1, T]$, predict $T+1$, advance one step, refit, repeat. Outside the time-series setting, two further tools work across model classes. The Kolmogorov-Smirnov test measures the maximum vertical gap between two empirical CDFs and, applied to model scores split by class, gives a complement to Gini that flags where on the score range the model discriminates best. The lift ratio and the cumulative lift curve express the model's value over the population base rate at any chosen cut-off, which is the form a commercial user actually wants. With those four, plus a closing recap of the bias-variance trade-off as it runs through every previous stage, the evaluation toolkit is complete.

Feynman test A regression model predicts loan amount and a classification model predicts default; both can be checked because the rows are unordered. A forecasting model predicts next quarter's default rate from last quarter's, and the order matters. If you split that series at random, the model has already seen the future when it predicts the past, and the test score is fiction. The cure is to evaluate the model exactly the way it will be used in production: train only on history, score only on the next observation, then add that observation to history and repeat. The autocorrelation checks then ask a separate question: once the model has done its best, is there any pattern left in the residuals that a better model would have captured?
What's beyond the syllabus Textbooks present the KS statistic as a normality test on residuals. In credit risk practice the same statistic does heavier work: applied to model scores conditional on the binary outcome (goods versus bads), it produces the two CDFs whose maximum vertical gap is the KS bands metric, regulatory cousin to Gini. Gini compresses the whole curve to a single number; KS bands tells you where on the score range the model separates best, which is the question portfolio managers actually ask when they pick a cut-off. The same logic generalises beyond credit: KS bands gives a decile-by-decile complement to AUC whenever the operating point is part of the decision.

Step 2

Why this matters

Three reasons forecasting evaluation needs its own machinery. First, residuals from a time-series model are not exchangeable. Under a correctly specified model with IID errors, the residuals should themselves be uncorrelated; that is the same condition standard regression diagnostics assume, transplanted to the time domain. When residuals show significant autocorrelation, the model has fit the conditional mean wrong: it has missed a lag effect (an AR term the model class did not include), a seasonality (a quarterly or annual cycle), or a level shift (a regime change the model treats as noise). The standard MSE and $R^2$ on a hold-out are silent on this; both can look healthy while the residual ACF screams that there is structure left on the table. Without an autocorrelation diagnostic, the model passes evaluation and fails the moment it has to forecast the cycle it has not learned.

Second, random train-test splits leak the future into training. A random split on a temporal dataset puts February 2024 in training and January 2024 in test, then asks the model to predict January 2024 having seen February 2024. The test score that comes out is biased upward by however much the dependent series is autocorrelated, which on macroeconomic and credit series is a lot. Walk-forward backtesting is not a refinement of the random split; it is a different evaluation procedure that asks the only honest question, namely how the model would have performed if deployed at each historical point in time. Every metric the model is judged on (RMSE, MAE, MAPE, Gini on a forecast horizon) is recomputed on out-of-sample one-step-ahead predictions assembled across the backtest. The result is what the model would have done in production; the random-split result is what the model would have done if it could time-travel.

Third, some diagnostics need to work across model classes. The KS test compares two empirical distributions without assuming what they look like, which makes it portable: residual normality for a regression, score separation for a classifier, distribution shift between training and production. Lift and cumulative lift translate any model's score into the commercial language of "how much better than random at the top decile", which is what a customer manager, a fraud reviewer, or a credit officer actually needs. These are not extras; they are the diagnostics that survive when the model class changes from linear regression to gradient-boosted tree to neural network and the metrics have to remain comparable.

Vignette from the field A retail PD model was extended to forecast portfolio default rate one quarter ahead, with the same logistic specification re-fitted on the latest snapshot. The team reported a hold-out $R^2$ of 0.71 from a random 80-20 split on the historical panel. At go-live the quarter-ahead forecasts missed the actual default rate by a factor of two and the supervisor asked for the backtest. The walk-forward exercise (refit each quarter on history only, predict the next quarter, advance) produced an $R^2$ of 0.08. The random split had silently used 2023 data to predict 2022 and 2021. The residual ACF on the original specification showed a significant spike at lag one that no one had checked. The two diagnostics together would have caught the problem six months earlier.
Step 3

The mental model

Hold this picture. A walk-forward backtest moves a window through time, refitting the model at each step and predicting the next observation. The series of one-step-ahead predictions, never having seen its own future, is then scored with whatever metric is appropriate (RMSE for a continuous target, Gini for a binary one). Autocorrelation tests run alongside, checking that each refit produces residuals with no leftover structure. The KS and lift diagnostics close the toolkit by reporting the model in the form a commercial user reads.

Three things to read off the diagram. The training window in each row stops strictly before the prediction it produces; that is the no-leakage property. The collection of violet predictions is the only data scored, and it is scored with the same metrics used elsewhere in this module (RMSE, MAE, MAPE for continuous; accuracy, F1, Gini for binary). The choice between an expanding window (each iteration grows training) and a rolling window (each iteration drops the oldest observation as well as adding the newest) is a separate decision about whether old observations remain representative; for slowly-drifting series the expanding window uses more data, and for fast-drifting series the rolling window adapts more quickly.

Step 4

The detail

Autocorrelation of residuals

Under a correctly specified model with IID errors, the residuals $r_t = y_t - \hat{y}_t$ should themselves be a white-noise sequence: zero mean, constant variance, and zero autocorrelation at every non-zero lag. Significant autocorrelation in the residuals means the model has not extracted all the signal: an AR or MA term has been omitted, a seasonal cycle has been missed, or a level shift has been treated as noise. The diagnostic is the same whether the model is a regression with a time index, an exponential smoothing model, or an ARIMA fit; the residuals are the place to look.

Three tools cover the practical cases. The autocorrelation function plot (ACF plot) shows the sample autocorrelation $\hat{\rho}(k)$ of the residuals at each lag $k$, with confidence bands around zero; any spike outside the band is evidence of leftover structure at that lag. A spike at lag 1 indicates an omitted AR(1) component; spikes at lags 12 (monthly data) or 4 (quarterly) indicate seasonality. The Durbin-Watson statistic is a single-number summary aimed specifically at first-order autocorrelation,

$$DW = \frac{\sum_{t=2}^{T}(r_t - r_{t-1})^2}{\sum_{t=1}^{T} r_t^2}.$$

The statistic is approximately equal to $2(1 - \hat{\rho}_1)$ where $\hat{\rho}_1$ is the lag-1 residual autocorrelation, so $DW$ ranges between 0 and 4. A value near 2 means $\hat{\rho}_1$ is near zero and there is no first-order autocorrelation. Values close to 0 indicate strong positive autocorrelation (residuals of the same sign cluster together, the model is systematically under- or over-shooting in runs); values close to 4 indicate strong negative autocorrelation (residuals flip sign at each step). The usual rule of thumb is that values between 1.5 and 2.5 are unproblematic; values outside this range warrant investigation. The OLS regression in the notebook on credit data reports $DW = 1.996$, comfortably inside the safe range for a cross-sectional fit (and not very informative for a model that was not temporal in the first place; the test is most useful when the rows really are ordered in time).

The Ljung-Box test generalises the question to joint autocorrelation up to lag $h$,

$$Q(h) = T(T+2) \sum_{k=1}^{h} \frac{\hat{\rho}_k^2}{T - k},$$

where $T$ is the sample size and $\hat{\rho}_k$ is the sample autocorrelation at lag $k$. Under the null that the residuals are independently distributed up to lag $h$, $Q(h)$ is approximately $\chi^2$ with $h$ degrees of freedom (adjusted downward by the number of fitted ARIMA parameters when applied to residuals). A small p-value rejects independence and indicates significant autocorrelation at one or more of the lags from 1 to $h$. Ljung-Box is the standard portmanteau test reported in time-series software (Python's statsmodels.stats.diagnostic.acorr_ljungbox, R's Box.test with type = "Ljung-Box") and is the workhorse residual check for ARIMA, exponential smoothing, and state-space models.

When autocorrelation is detected, the corrective action depends on the pattern. Positive serial correlation at low lags suggests adding lagged dependent or independent variables to the specification. Negative serial correlation often signals overdifferencing (the model has applied $\Delta$ one more time than the series required). Spikes at seasonal lags call for seasonal dummies or a seasonal differencing term. A model with residual autocorrelation has not been falsified outright, but it has been told there is signal it failed to extract; the only honest response is to extend the specification and refit.

Backtesting: walk-forward evaluation

The standard train-test split assumes rows are exchangeable. Time-series rows are not, and a random split puts later observations into training and earlier ones into test, which is leakage of the future into the past. Backtesting replaces the split with a walk-forward scheme that mimics how the model would have been used at each historical point. Fix an initial training window $[1, T_0]$ that is large enough to fit the model. Fit the model on that window. Predict the next observation, $T_0 + 1$. Record the residual. Now extend (or roll) the training window by one step to $[1, T_0 + 1]$ (or $[2, T_0 + 1]$ for a rolling window), refit the model, and predict $T_0 + 2$. Continue until the present. The collection of one-step-ahead residuals is the backtest output, scored with the usual regression or classification metrics (RMSE, MAE, MAPE, Gini, AUC, F1, depending on the target).

Two variants matter. An expanding-window backtest grows the training set by one observation at each step, using every observation that exists at forecast time; it uses the most data and is appropriate when the data-generating process is stationary or slowly drifting. A rolling-window backtest keeps the training window at a fixed length, dropping the oldest observation as the newest arrives; it adapts faster to regime change and is appropriate when older observations are no longer representative (interest-rate regimes, COVID-era data, post-Basel-IV portfolios). The choice is empirical: run both, compare backtest error, pick the one that wins on stability and on metric.

Two extensions are common enough to deserve names. Multi-step backtests predict $h$ steps ahead rather than one, which is what the model will actually do in production for any horizon longer than the data frequency; the same walk-forward logic applies, with the prediction taken at step $T_0 + h$ instead of $T_0 + 1$. Time-series cross-validation (scikit-learn's TimeSeriesSplit) is an automated version of the expanding-window backtest with a fixed number of folds, useful for hyperparameter tuning when a full step-by-step walk is too expensive. Both are walk-forward in spirit; both preserve the no-leakage property; both score the model on observations strictly later than the training window that produced the prediction.

The metric reported from a backtest is the same as the metric reported from a hold-out: RMSE on a continuous forecast, MAPE when the operating user thinks in percentages, Gini or AUC on a binary forecast, accuracy or F1 on a classified outcome. The numerical value typically degrades compared to the random split, sometimes dramatically; that is the cost of removing the leakage. A model whose backtest score is materially worse than its random-split score has been overfitting to features that include information about the future, and the backtest score is the one that matters.

Kolmogorov-Smirnov test and KS bands

The Kolmogorov-Smirnov statistic measures the largest vertical gap between two empirical cumulative distribution functions. Given samples with empirical CDFs $F_1(x)$ and $F_2(x)$,

$$D = \sup_{x} |F_1(x) - F_2(x)|.$$

The two-sample KS test rejects the null hypothesis that the samples come from the same distribution when $D$ is large; the one-sample version replaces $F_2$ with a hypothesised distribution $F_0(x)$. The test is non-parametric: it makes no assumption about the shape of either distribution.

Three uses of KS recur. First, as a residual check: applied to the residuals of a regression against a normal reference, KS tests normality without the parametric structure of a Shapiro-Wilk; it is robust on large samples where Shapiro-Wilk's significance becomes uninformative. Second, as a distribution-shift check: applied to a feature in training versus the same feature in production, a significant KS warns that the distribution has drifted, which is what a monitoring pipeline (stage 5 of the pipeline) reports. Third, the credit-risk use just illustrated: applied to model scores conditional on outcome, $F_1(x)$ is the CDF of scores for goods and $F_2(x)$ is the CDF for bads; the KS statistic is then the maximum cumulative separation between them as the score ranges. Higher KS means the model concentrates more bads at low scores and more goods at high scores; KS bands of 0.3 to 0.5 are typical for retail PD scorecards, and Gini and KS bands are reported together because they measure complementary aspects of the same ROC.

Lift ratio and cumulative lift

Most operational uses of a classification model rank observations by score and apply a decision to the top fraction (the top decile gets a marketing call, the top quintile gets manual underwriting, the bottom 5 per cent gets auto-decline). The metric that matches this use is lift: how much more concentrated are positives in the top fraction than in the population as a whole. For a chosen group (often a score decile),

$$\text{Lift} = \frac{\text{positive rate in the group}}{\text{positive rate in the whole population}}.$$

A lift of 1 means the group is no better than random; a lift of 3 means three times the base rate of positives lands in the group, so the model has triple the precision of a random selection at that volume. Lift is the metric a commercial user asks for unprompted: "if I act on the top 10 per cent of scores, how much better than random am I". It is fully determined by the ROC curve, but it presents the same information in the units of decision-making rather than the units of probability theory.

Cumulative lift extends the single-decile number to a curve. Sort observations in descending order of score; for the top $k\%$ of the population, the cumulative lift is the proportion of all positives captured in that top $k\%$ divided by $k\%$ itself. Plotting cumulative lift on the y-axis against population fraction on the x-axis gives the lift curve: a horizontal line at 1 is the random model; a model with discriminatory power starts high (positives are concentrated in the top scores) and decays toward 1 as the cumulative fraction approaches 100 per cent (at the whole population, every model captures every positive). The area between the curve and the random line is a Gini-equivalent summary, and the y-intercept of the lift curve (lift at the smallest decile) is the headline number for tight cut-offs (top 1 per cent fraud queues, top decile collection calls).

A small worked example makes the calculation concrete. Suppose a binary target has 30 per cent positives overall, and the top decile of model scores contains 75 per cent positives. The lift at the top decile is $0.75 / 0.30 = 2.5$; the model is 2.5 times better than random at that operating point. The notebook's cumulative_classification_lift implementation reproduces this construction: it sorts by predicted probability, computes the running positive rate, and divides by the overall positive rate; the first array element is the lift at the top observation, the last element is exactly 1 (the lift over the whole population is, by construction, the population rate divided by itself).

Closing the bias-variance loop

This is the final lecture of the assessment block and the appropriate place to recap the bias-variance trade-off as it has run through every earlier stage of the pipeline. The trade-off is not local to model fitting; it appears at every decision point, and overfitting can be introduced at each of them.

At features (sub-module 01), selecting too many features inflates variance: every additional feature is a parameter to estimate, and the model fits noise in the training rows. Sub-module 01 lecture 4 on feature selection is the bias-variance trade-off in column space: keep too few features and the model underfits (bias); keep too many and it overfits (variance). At split (sub-module 02), repeatedly choosing hyperparameters on the validation set leaks validation information into the model and turns validation into a second training set; the test set then plays the role validation was supposed to. At fit (sub-module 03), model capacity is the direct lever on bias and variance: a linear model is high bias and low variance, a fully-grown decision tree is the opposite, an ensemble averages many low-bias high-variance models toward a lower-variance result. At tune (sub-module 06), hyperparameter search traces the U-shaped curve of test error against model complexity and picks the minimum; the standard mistake is to read the training-error curve instead, which is monotonically decreasing and never picks anything. At evaluate (this sub-module), the test set is the only honest read on the model's true generalisation; touching it before the final report converts it into validation, and the model loses its unbiased estimate. At interpret (sub-module 08), the choice between white-box and black-box methods is the bias-variance trade-off applied to explanations: a linear-regression coefficient is a high-bias, low-variance interpretation of the effect (it forces linearity in $X$ but is stable across resamples); a SHAP value on a tree ensemble is a low-bias, high-variance interpretation (it can capture any shape of effect but moves around between resamples). The whole course is the same trade-off applied at six different scales.

The bias-variance identity Under squared-error loss, the expected test error at a point $x_0$ decomposes exactly into three components: $\mathbb{E}[(y_0 - \hat{f}(x_0))^2] = \operatorname{Var}(\hat{f}(x_0)) + \operatorname{Bias}(\hat{f}(x_0))^2 + \sigma^2$, where $\sigma^2$ is the irreducible noise in $y_0$. The first two are model-dependent and trade off against each other; the third is a property of the data and no model can reduce it. Every choice in the pipeline shifts the first two; no choice touches the third. Evaluation reports the sum.
Step 5

Pitfalls

Four failure modes account for almost every forecasting and model-agnostic evaluation incident. Each looks fine in a notebook and breaks in production.

Random split on temporal data The default train_test_split with shuffle=True randomly permutes the rows, which on a time series puts later observations in training and earlier ones in test. The reported test error is biased downward by however much the series is autocorrelated. The fix is structural: use a walk-forward backtest or TimeSeriesSplit for cross-validation; never shuffle when the rows have a time index. The diagnostic that catches the symptom afterwards is a comparison of backtest score against random-split score, which on a leaked model differ by an order of magnitude.
Refitting the model only once A common shortcut is to fit on $[1, T_0]$, predict every observation from $T_0 + 1$ to $T$ without refitting, and call the resulting errors a backtest. This is a hold-out, not a walk-forward backtest, and it underestimates the model the further into the future the predictions go (the model never sees the more recent observations). The fix is to refit at each step (or at a regular cadence shorter than the prediction horizon); the cost is computational and is the price of an honest forecast.
Ljung-Box without degrees-of-freedom correction Applied to raw observations, Ljung-Box is $\chi^2$ with $h$ degrees of freedom. Applied to residuals from an ARIMA$(p, d, q)$ fit, the effective degrees of freedom are $h - p - q$, because the model has already used $p + q$ parameters to remove autocorrelation. Software that defaults to the wrong degrees of freedom understates the p-value and over-accepts the null of no autocorrelation. In Python, acorr_ljungbox takes a model_df argument for this correction; in R, the fitdf argument on Box.test does the same.
Lift at a single decile reported without the curve A headline "lift of 3 at the top decile" sounds impressive but says nothing about behaviour at other operating points. A model with a sharp top-decile lift and a flat curve elsewhere is useful only for cut-offs at exactly the top decile; a model with a smooth decay across deciles is robust to changes in operating point. The fix is to report the cumulative lift curve alongside any single-decile number, and to choose the operating point before reporting lift rather than after (otherwise the chosen decile is itself an overfit to the validation set).
Step 6

Synthesis and what's next

Forecasting evaluation extends the regression and classification toolkits to the case where rows are ordered in time. Residual autocorrelation diagnostics (ACF, Durbin-Watson, Ljung-Box) ask whether the conditional mean has been fully captured; significant autocorrelation means structure remains, and the specification must be extended. Walk-forward backtesting replaces the random train-test split with a procedure that never shows the model its own future; the resulting score is what the model would have produced in production, and it is the only score that matters for a deployed forecaster. The Kolmogorov-Smirnov statistic measures the maximum vertical gap between two empirical CDFs and serves as a normality check, a distribution-shift check, and (applied to good and bad score distributions) the regulator-facing KS bands metric. The lift ratio and the cumulative lift curve translate model scores into the commercial language of "how much better than random at the top fraction", which is the form decisions are actually made in.

What this lecture deliberately did not do. It did not derive an ARIMA or state-space model; that is the job of statistics lecture 6. It did not introduce probabilistic forecasting (prediction intervals, fan charts, scoring rules like the CRPS); those are extensions of the same machinery and are covered in the time-series sub-module. It did not address structural breaks or regime-switching models, where the residual diagnostics will fail in a different way (the model is stable within each regime but not across them); those need their own evaluation framework. The four tools introduced here, applied alongside the regression and classification metrics of the previous two lectures, cover the F107-level requirement and the day-to-day commercial requirement.

Lecture 39 begins sub-module 08 on model interpretation. Having validated the model on every metric the pipeline supports, the next question is what the model is actually doing: which features matter, how do they combine, where does the prediction come from for a given row. The interpretation toolkit (white-box reading of coefficients and feature importances, black-box methods like LIME and SHAP, partial dependence and ICE plots) is the bridge between a validated model and a deployed one, because no production user, regulator, or business stakeholder will accept a number they cannot explain.
