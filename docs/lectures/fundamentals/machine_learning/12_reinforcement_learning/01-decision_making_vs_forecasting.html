Lectures / Machine learning / Reinforcement learning

Decision-making versus forecasting

Every model in this course, from the first GLM to the largest language model, has answered a variant of one question: given this input, what is the best prediction of an outcome the model itself has no influence over. Reinforcement learning breaks that assumption entirely. This lecture makes the conceptual break explicit before any of the mathematics, because the single most common source of confusion for a forecasting-trained practitioner meeting reinforcement learning for the first time is not a missing formula, it is an unexamined habit of thought.

Step 1

The 30-second version

In every model this course has covered so far, the modeller observes covariates $X$, generated by some process entirely outside the model's control, and predicts an outcome $Y$; nothing the model outputs feeds back to change what $X$ or $Y$ would have been. Reinforcement learning (RL) studies a different structure entirely: an agent observes a state, takes an action, and that action directly changes the state the agent finds itself in next, together with a reward received for having taken it. There is no fixed, correct label to predict, only a reward signal to be maximised over time, and the agent's own past actions are themselves part of what generated the data it now has to learn from, a feedback loop nothing earlier in this course has had to contend with. The actuarial framing that will recur throughout this sub-module is premium control: a pricing action taken today (raising or lowering a premium) changes tomorrow's exposure, retention, and claims experience, which in turn changes what the right pricing action is tomorrow, precisely the closed loop a supervised forecasting model is structurally unable to represent.

Feynman test A weather forecaster predicts tomorrow's rainfall as accurately as possible, fully aware that nothing in the forecast changes whether it actually rains. A river-lock operator, deciding how much water to release today, faces a genuinely different problem: today's release decision directly changes tomorrow's water level, which changes what the right release decision is tomorrow, and the operator is graded not on how accurately they predicted the water level but on how well the sequence of their own decisions kept the river within safe and useful bounds over time. Every model earlier in this course has been the weather forecaster; this sub-module is about building the lock operator.
Where this sits in the ML world This lecture is the single conceptual pivot of the entire course: everything before this sub-module, including the generative models of sub-modules 10 and 11, still answers a variant of "what does the data look like", with the agent itself never changing the data-generating process. This sub-module is the one place in the course where the model's own output feeds back into what happens next, a genuinely different mathematical object requiring genuinely different tools, developed from first principles across the rest of this sub-module.
Step 2

Why this matters

Three reasons this conceptual break earns dedicated attention before a single equation, rather than being treated as an implementation detail of an otherwise-familiar supervised problem.

First, several genuine actuarial and insurance problems are decision problems, not forecasting problems, and treating them as the latter produces a structurally wrong model: pricing, claims-handling triage that affects future claimant behaviour, and reinsurance retention-limit setting all involve actions that change the future data the business will observe, and a conventional supervised model, however well it is fitted and validated, has no native way to represent that a different action today would have led to a different, better tomorrow.

First and second, the reward signal in RL is fundamentally weaker and more delayed than a supervised label: a supervised model is told the correct answer for every training example; an RL agent is only ever told how good the consequences of its action turned out to be, often only after a long delay and confounded by everything else that happened in between, a genuinely harder learning problem that every technique in this sub-module is built to address.

Third, the RL literature's vocabulary genuinely overlaps with, but does not mean the same thing as, this course's earlier vocabulary, and conflating the two is the single most common source of confusion for a practitioner arriving from a forecasting background: "value function" here is not a regression prediction in the earlier sense, "policy" is not a fitted classifier in the earlier sense, and treating them as such leads directly to the wrong intuition about what each object actually represents, developed carefully across this sub-module.

Vignette from the field A pricing team, asked to build a model recommending premium adjustments to maximise long-run profitability, initially framed the problem as an ordinary supervised regression: predict the profit outcome associated with each of several candidate premium levels, using historical data on premiums charged and the profit that resulted, then recommend whichever candidate premium the model predicted would be most profitable. The model performed poorly in a live pilot, recommending premium changes that looked good in the historical data but that, once actually deployed, provoked retention and claims-mix shifts the historical data had never contained any information about, because every premium level actually charged historically had itself been chosen by an existing pricing process that avoided precisely the extreme adjustments the new model was now recommending. The team's error was treating a decision problem, where the action taken changes the future population actually observed, as a forecasting problem, where the training data was assumed to already contain examples of the consequences of actions nobody had actually taken; this sub-module's premium-control framing, developed properly in the actuarial-applications sub-module, is the direct, principled fix.
Step 3

The mental model

Hold one picture: a supervised model as a single, static arrow from input to output with no feedback loop at all, against an RL agent locked in a closed loop with its environment, where every action changes the very state the next decision must be made from.

Two slogans. There is no ground-truth label, only a reward. Nobody tells the agent what the "correct" action was; the agent only ever finds out how good the consequences of the action it actually took turned out to be. The data the agent learns from is a consequence of its own past decisions. This is the single fact that breaks every earlier assumption in this course about training data being generated independently of the model being fitted to it, and it is the fact the vignette's pricing team's initial framing failed to account for.

Step 4

The detail

Actions change the process; forecasts do not

The defining structural feature of a reinforcement-learning problem, restated precisely: the agent's action at time $t$ is a genuine causal input to the state and reward observed at time $t+1$, not merely a prediction about them. A weather forecast, however accurate, has zero causal effect on whether it actually rains; a pricing decision has a direct, measurable causal effect on next period's exposure, retention, and claims mix. Any historical dataset of "premium charged and profit observed" therefore only ever contains examples of the consequences of the specific pricing policy that was actually in force when the data was collected, not the consequences of policies nobody ever tried, exactly the gap the vignette's team fell into by treating the problem as ordinary supervised regression.

Rewards instead of correct answers

A supervised model's loss function compares a prediction $\hat{Y}$ against a known, fixed ground truth $Y$ for every training example. An RL agent instead receives a reward, a scalar signal indicating how good the immediate consequence of an action was, with no notion anywhere in the framework of a single "correct" action to have taken instead. This is a genuinely weaker training signal: the agent must learn, purely from the pattern of rewards received across many actions and outcomes, which actions tend to lead to good long-run consequences, without ever being told directly what the best action would have been in any specific instance.

The premium-control framing

Casting a pricing decision as a reinforcement-learning problem means treating the premium charged to a policyholder (or a class of policyholders) as the agent's action, the policyholder's or portfolio's current state (recent claims experience, competitor pricing, market conditions) as the environment's state, and some combination of retained profit, retention, and solvency-constraint satisfaction as the reward. Framed this way, the genuinely hard part of the problem, that a pricing action taken today changes what state and reward will be observed tomorrow, is represented directly and honestly, rather than being smuggled past by an implicit and usually false assumption that the historical data already contains examples of every action's consequences. The actuarial-applications sub-module returns to this framing in full, including the multi-objective reward structure (profit, solvency, elasticity) a genuine pricing application requires.

A warning about terminology

The reinforcement-learning literature reuses several words from earlier in this course with genuinely different meanings, and this sub-module flags each divergence as it arises rather than assuming familiarity transfers automatically. A value function, developed in lecture 4, is an expected long-run cumulative reward under a specific policy, not a single-step regression prediction. A policy, also lecture 4, is a rule mapping states to actions (or a distribution over actions), a genuinely different object from a fitted classifier even though both can be represented by similar-looking function approximators. Treating these terms as synonyms for their earlier-course meanings, rather than reading each definition carefully as it is introduced, is the single most avoidable source of confusion for a reader arriving at this sub-module from the rest of the course.

Step 5

Pitfalls

Framing a genuine decision problem as a supervised forecasting problem Developed directly in the vignette: historical data on actions actually taken systematically under-represents, or entirely omits, the consequences of actions nobody actually tried, and a supervised model trained on that data has no principled way to extrapolate to a genuinely novel action's likely consequences.
Assuming a reward signal is as informative as a supervised label A reward tells the agent how good an outcome was, not what the best action would have been instead; every algorithm in the rest of this sub-module exists specifically to squeeze a workable learning signal out of this genuinely weaker form of feedback, and expecting RL to converge as quickly or as data-efficiently as supervised learning on a comparably sized dataset is a common, avoidable disappointment.
Conflating RL terminology with its earlier-course namesakes "Value", "policy", and several other terms mean something structurally different here than in the supervised or unsupervised sub-modules; reading each new definition on its own terms, rather than assuming the earlier meaning carries over, avoids a recurring and entirely avoidable source of confusion.
Deploying an RL-style decision system without accounting for the feedback loop it creates Because an RL agent's actions genuinely change the environment it operates in, a deployed pricing agent changes the very market and policyholder behaviour its own future training data will reflect; this is not a bug to be engineered away, it is the defining feature of the problem, and it demands governance attention (developed in the actuarial-applications sub-module) that a static supervised model never required.
Step 6

Synthesis and what's next

Every model built earlier in this course predicts an outcome generated by a process the model itself does not influence. Reinforcement learning studies an agent whose actions directly change the state and reward it will next observe, learning from a reward signal rather than a fixed correct answer, and facing a closed feedback loop where its own past decisions shape the very data it learns from. The premium-control framing, a pricing action changing tomorrow's exposure and claims experience, is the recurring actuarial illustration of exactly this structure, and the vignette's initial supervised framing shows precisely what goes wrong when the structure is missed.

The next two lectures build the two core ideas, exploration versus exploitation and incremental updating, inside the simplest possible setting, a single state with no transitions at all (the multi-armed bandit), before lecture 4 generalises everything to the full multi-state Markov decision process this lecture has been gesturing towards.
