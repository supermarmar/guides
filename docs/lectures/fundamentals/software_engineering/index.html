Course companion

Software engineering

A bachelor's-level software-engineering course for the working analyst and quant. Sixteen lectures, written in the tradition of Brooks, Knuth, and Beck. The spine is Python, but the principles transfer. Assumes you have written code before and would now like to write it deliberately.

How to use this

The lectures are sequenced bottom up. Part I builds the craft of writing code in a single file: style, idiom, language, and the unreasonable utility of regular expressions. Part II adds the two skills that nobody is taught and everyone improvises: testing and debugging. Part III turns the file into a document, an audience, and a diagram. Part IV turns the document into a team: project setup, version control, code review, continuous delivery, and the long tail of auto-generated documentation. Status badges show what is built (built), planned, or a gap (source note is a stub).

What is and is not covered

The course covers the engineering side of writing code that other people, including a future version of you, can read, run, and trust. It does not cover algorithms, data structures, computer architecture, networking, operating systems, or security as separate disciplines. Those have their own courses. Where they intrude, the lecture cites the canonical text and moves on. The course also stops short of distributed systems, microservices, and platform engineering; the curriculum here is meant to make you a competent author of working software at the scale of a small team and a single repository.

Every lecture is written to stand alone, with one canonical research paper or primary source cited per topic. The bibliography across the course covers the established literature, Brooks 1986, Dijkstra 1989, Naur 1985, Knuth 1984, Beck 2003, Humble & Farley 2010, Bacchelli & Bird 2013, plus the relevant Python Enhancement Proposals and tool documentation.
